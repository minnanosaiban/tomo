# 株価データ取得ツール

株価・適時開示・ニュース・決算短信・有価証券報告書の**取得**と、取得したデータの**品質チェック**を、ひとつの画面にまとめたツール「**株価データ取得ツール**」の解説です。連載「株価分析」（決算短信・有価証券報告書・株価データを使った検証）の元になるデータを、毎日きちんと貯めるために作りました。

- 連載：[株価分析](../blog/index.md)（記事の一覧）
- 動作環境：Windows の自分のパソコン（ローカルＷｅｂアプリ。公開サイトはありません）

このページは、ツールの使い方と、その仕組み、作るうえで判断したことの解説です。

## 株価データ取得ツールとは：取得と点検を、ひとつの画面で

連載の分析は、無料で入手できる次のデータを土台にしています。

| データ | 取得元 | 保存先 |
|---|---|---|
| 個別株の日足・5分足、マクロ指標 | yfinance | `data/prices/` |
| 適時開示 | TDnet | `data/news/tdnet/` |
| ニュース | RSS | `data/news/rss/` |
| 決算発表予定 | 決算スケジュール | `data/news/kessan_schedule/` |
| 決算短信 | XBRL | `data/statements/` |
| 有価証券報告書 | EDINET | `data/yuho_zip/` ほか |

取得のたびにスクリプトを個別に呼び、ログを見て、抜けや遅れを目で確かめるのは手間がかかります。そこで、**押すだけで取得でき、取得済みの期間と実行ログが見え、データの異常も点検できる**画面にまとめました。

取得の中身（どこから、どう取るか）は、これまでのスクリプトをそのまま使っています。このツールは、それらを**呼び出して、結果を見せる**だけです。

### 使い方

1. **ツールを起動する**：`data_hub\start.bat` を実行します。ブラウザが開き、画面が表示されます（アドレスは `http://127.0.0.1:8765/`）。終了するときは、黒いウィンドウを閉じます。
2. **「取得」モードで実行する**：取りたいデータのカードの「取得する」を押します。日付や日数が必要なカードには入力欄があります。
3. **まとめて実行する**：毎日の更新は「日次セット」、朝だけなら「朝セット」、遡って取りたいときは「期間指定の一括取得」を使います。
4. **実行ログで経過を見る**：画面の下に、各処理の状態・経過時間・最新の1行が出ます。行を押すと出力の全文が開きます。失敗した行は自動で開きます。
5. **「品質チェック」モードで点検する**：チェックを選んで実行し、結果の一覧を見ます。

実行できるのは**一度に1件**です。実行中は、ほかのボタンが押せなくなります。

### まとめて実行

| セット | 内容 |
|---|---|
| 日次セット | 適時開示 → （個別株・ニュース・決算短信・決算発表予定を並行して）→ マクロ指標 → 銘柄検出の事前計算。「最後にR2へバックアップ」にチェックすると、終わりにクラウドへ差分を送る |
| 朝セット | マクロ指標 → ニュース（米市場の確定値と、朝のニュース） |
| 期間指定の一括取得 | 開始日〜終了日の、適時開示と決算短信 |

日次セットは、**順番に意味がある**ので段階に分けて実行します。決算短信の取得は、先に保存した適時開示の一覧を読むため、適時開示を最初に済ませます。取得先が別々のもの（株価・ニュース・決算短信など）は、同時に動かして時間を縮めます。ただし、個別株とマクロ指標はどちらも yfinance から取るので、同時には動かさず、個別株のあとにマクロ指標を取ります（理由は「[株価の取得は、速さより yfinance への配慮を優先した](#yfinance)」）。

### 個別に取得できるデータ

| グループ | カード | できること |
|---|---|---|
| 株価 | 個別株 OHLCV | 日足・5分足。「日足のみ」「5分足のみ」、日数・年数を指定可 |
| 株価 | マクロ指標 | 米株・先物・為替・原油など |
| 開示・ニュース | 適時開示（TDnet） | 指定日の開示一覧 |
| 開示・ニュース | ニュース（RSS） | 本日分 |
| 開示・ニュース | 決算発表予定 | 今後のスケジュール |
| 財務 | 決算短信 XBRL→JSON | 指定日の決算短信を取得・変換 |
| 財務 | 有報インデックス | EDINET の書類一覧 |
| 財務 | 有報 XBRL | 有価証券報告書の ZIP（時間がかかる） |
| 加工 | セクター再生成 | ウォッチ銘柄からセクター別の一覧を作り直す |
| 加工 | 銘柄検出の事前計算 | 全銘柄の指標をあらかじめ計算して保存（約20〜30秒） |
| 加工 | R2バックアップ | クラウドへ差分を転送 |

各カードには、**取得済みの期間と件数**（例：「2023-10-10 〜 2026-10-07（2595 銘柄）」）が出ます。「どこまで貯まっているか」を、取る前に確かめられます。

### 品質チェック

取得したデータが**使える状態か**を点検します。結果は「問題なし」「要確認」「NG」「参考」で示します。

| チェック | 何を見るか | 判定の基準 |
|---|---|---|
| 株価・マクロの検証 | データの遅れ、終値の欠損、株式分割の取り込み漏れの疑い | 最新日が基準営業日より5日超遅れ → 要確認。終値が空 → 要確認。前日比が約0.55倍以下／1.8倍以上 → 参考（分割・統合の疑い） |
| ニュース・開示の日付抜け | ニュースと適時開示の日次ファイルに、営業日なのに無い日がないか | 直近60日の営業日で、ファイルが無い日を数える |
| 決算短信の主要指標欠損 | 売上・営業利益・純利益などが空の決算短信 JSON | 既存のチェックスクリプトの結果（実行ログに出る） |
| 決算短信の収集状況 | 銘柄ごとの、決算短信の収集の進み具合 | 既存のスクリプトの結果（実行ログに出る） |

「株式分割の疑い」は、株価の取り込みで特に厄介な点を拾うためのものです。株価データは通常、分割後の値に補正されて届きますが、補正が漏れると、ある日を境に株価が半分や倍になった**偽の急変**が混ざります。分析の結果を歪めるので、早めに見つけられるようにしました。

> **チェック結果の読み方**：日付抜けのチェックは、**祝日を営業日として数えます**。「なし」と出た日が祝日なら、異常ではありません。データが本当に欠けているかは、その日が開場日だったかと合わせて判断します。

## 全体の構成

```
ブラウザ（画面）
   │  取得・チェックの指示 / 状況の問い合わせ（数秒ごと）
   ▼
data_hub/server.py   ← FastAPI（このパソコンの 127.0.0.1 だけで待ち受け）
   │
   ├─ catalog.py … 取得メニューの定義、取得済み期間の集計
   ├─ quality.py … 品質チェック（株価・日付抜け）
   └─ app/lib/fetch_jobs.py … 取得の実行役（別のプロセスとして起動し、出力を1行ずつ記録）
          │
          ▼
   ingest/ のスクリプト群（取得・変換） → data/ に保存
```

- **画面**：ビルド工程のない素の HTML / CSS / JavaScript です。見た目は、サイドノート作成ツールと同じ配色（明るいグレーの背景、白いカード、ダークのボタン）に揃えました。
- **サーバー**：[FastAPI](https://fastapi.tiangolo.com/) の小さなサーバーです。画面に渡すのは、取得メニュー、取得済み期間、実行の状況、チェック結果だけです。
- **取得の実行**：各スクリプトは、**別プロセス**として起動します。出力は1行ずつ受け取って記録し、画面が問い合わせたときに最新の状況を返します。画面を開き直しても、動いている取得は止まりません。
- **取得ロジック**：`ingest/` のスクリプトを呼ぶだけです。夕方のバッチ（`run_evening.bat`）や、タスクスケジューラの定時実行も、そのまま使えます。

### 実行の安全策

- **同時に動かすのは1件**です。取得が重なって、同じファイルを同時に書き換えるのを防ぎます。実行中に別の取得を求めると、サーバー側でも断ります。
- **品質チェックは読み取り専用**です。株価やニュースのファイルを開いて調べるだけで、書き換えません。
- 待ち受けは `127.0.0.1`（このパソコン自身）に限っています。同じネットワークの他の機器からは使えません。

## 作るうえで判断したこと

### Streamlit から、独立したアプリに分けた

以前は、分析用の Streamlit アプリの1ページに取得の画面を置いていました。分析と取得は役割が違うので、取得を独立させました。

- 取得は、画面を再描画するたびにスクリプトが走り直す Streamlit と相性がよくありません。取得中にページを移ると、画面から結果が消えるといった不便がありました。
- 取得の画面は、分析アプリを立ち上げなくても開けるほうが、毎日の作業に向きます。

分析アプリ側のメニューからは「データ取得」を外し、取得は新しいツールに一本化しました。

### 取得の中身は、書き直さなかった

動いている取得スクリプトを作り直すと、データの形が変わったり、これまでの運用が崩れたりするおそれがあります。画面だけを新しくし、取得は**既存のスクリプトを呼ぶ**形にしました。例外は株価の取得で、yfinance への配慮のために中身を見直しました（次の項目）。保存するファイルの形は変えていません。

### 株価の取得は、速さより yfinance への配慮を優先した

株価は yfinance から取っています。yfinance は無料で公開されている仕組みで、Yahoo の公式な API ではありません。短い時間に多くの要求を送ると相手に負担をかけますし、制限を受けて取得できなくなるおそれもあります。まとめて取ったり並列に動かしたりすれば速くできますが、**時間がかかっても、相手に負担をかけない取り方**を選びました。

- **1銘柄ずつ順番に取り、1回ごとに0.5秒あける**：一括取得や並列化はしません。他の取得スクリプト（適時開示や EDINET）と同じ水準の間隔です。
- **日足は、増えた分だけ取る**：以前は毎日、全銘柄の3年分（約750日分）を取り直していました。今は、手元のファイルの最終日の少し前から当日までだけを要求し、手元のデータに継ぎ足します。1回の要求で受け取るデータは、数百分の一になりました。
- **補正があった銘柄だけ、全期間を取り直す**：株式分割や配当があると、過去の株価もさかのぼって補正されます。継ぎ足しのときに、手元のデータと重なる日の終値を見比べ、ずれていればその銘柄だけ3年分を取り直します。補正前と補正後の値が混ざるのを防ぎます。
- **制限を受けたら、長めに待つ**：レート制限を受けたときは2分待って、1回だけ取り直します。上場廃止などでデータが無い銘柄は、取り直しません（無駄な要求を増やさないため）。取れなかった銘柄は、最後にまとめて実行ログに出します。
- **個別株とマクロ指標を同時に動かさない**：どちらも yfinance なので、日次セットでは順番に実行します。

そのぶん、取得には時間がかかります。個別株は日足と5分足を合わせて約4,200回の要求があり、間隔をあけるだけで30分以上増えます。毎日の更新は夕方の定時バッチで自動に回すので、待ち時間よりも、相手に迷惑をかけずに長く使い続けられることを優先しました。

### 公開せず、自分のパソコンだけで動かす

取得には、株価や開示の取得・ファイルへの書き込みが必要です。静的なサイトとして公開する形（ブラウザだけで完結するツール）には向きません。さらに、データの提供元の利用条件上、取得したデータそのものは公開しません。そのため、**ローカルのＷｅｂアプリ**にしています。

### 品質チェックを、取得と同じ画面に置いた

取得して終わりにせず、「ちゃんと取れているか」をすぐ確かめられるようにしました。分析で数字がおかしいと気づいてから原因をたどるより、取得の直後に異常を見つけるほうが、修正が簡単です。

## できないこと・注意点

- **実行中の取得を、画面から止める機能はありません**。止めたいときは、起動した黒いウィンドウを閉じます。
- **実行ログは、サーバーを止めると消えます**。残したい場合は、定時バッチのログ（`logs/`）を使います。
- **Windows が前提です**。R2バックアップは、別途 rclone の設定が必要です。
- 日付抜けのチェックは、祝日を考慮していません（上記）。
- データの提供元の仕様が変わると、取得が失敗したり、0件になったりすることがあります。実行ログで、各取得元の件数を確認してください。
