# 英文読解の復習アプリ（English Reading Review）

<p class="about-work-links">
<a class="arrow-link" href="https://english-reading-review.scratch-2026-10-07-cb3f9c.workers.dev/" target="_blank" rel="noopener"><i class="bi bi-box-arrow-up-right"></i> 公開サイト</a>
<a class="arrow-link" href="https://github.com/minnanosaiban/eng_reading" target="_blank" rel="noopener"><i class="bi bi-github"></i> GitHub</a>
</p>

英文と和訳のペアを登録し、**読んでいて引っ掛かった単語・熟語・フレーズ**を選んで★登録し、文脈つきで復習するアプリです。単語帳ではなく、「自分が英文を読んでいてつまずいた表現」を蓄積する帳面として作りました。サーバーはなく、静的ファイルだけで動きます。**入力した英文・和訳・復習データは、アプリからは外へ送りません。** 読み上げはブラウザの Web Speech API が行います。

このページは、その仕組みと、作るうえで判断したことの解説です。

## 何をするアプリか

アプリの中心は、この4つの操作の輪です。

> 英文を読む → 引っ掛かった語句を選んで★登録 → 復習する → 元の英文へ戻って読み直す

設計上の優先順位も、この順で決めました。**登録したデータが失われないこと、選んだ文字列と英文中の位置を正確に保持できること、読む流れを止めない（選ぶ → 1操作で登録）こと**が先で、見た目は最後です。

### ほかの英語アプリとの役割分担

| アプリ | 役割 |
|---|---|
| [英語の音の聞き比べアプリ](eng-sound.md) | 音として聞き取れない箇所を調べる |
| [英文学習アプリ](eng-sentence.md) | 英文の構造（区切り・品詞・文法）を解析して学ぶ |
| 英文読解の復習アプリ（このアプリ） | **意味としてすぐ出てこなかった表現**を蓄積し、復習する |

語句は、**英文からの★登録だけ**で増やします。単語だけを直接入力する機能は、あえて作っていません。語句を必ず元の英文とセットで覚えることが、このアプリの役割だからです。英文ごとの「読めた」状態の管理や、学習統計も作っていません。「読める英文が増えた」ことは、★登録した語句の復習と、元の英文の読み直しで確かめます。

## 全体の構成

React と TypeScript（strict）で書き、Vite でビルドしています。状態管理ライブラリやUIライブラリ、CSSフレームワークは入れず、`useReducer` と素のCSSだけで書いています。

```
src/
  App.tsx            状態を持つ（useReducer）。自動保存・ナビ・通知・取り消し
  appReducer.ts      更新アクション。ロジックは logic/ の関数を呼ぶだけ
  logic/             Reactに依存しない純粋関数（単体テストの対象）
    normalize.ts       正規化・範囲調整・キー生成
    sentence.ts        文の切り出し
    register.ts        ★登録・重複処理
    relocate.ts        英文を編集したときの位置の再設定
    reviewQueue.ts     出題順
    segments.ts        下線表示のための区間分割
    materials.ts       教材の追加・更新・削除
    items.ts           意味メモ・判定・削除
  storage/           localStorage の読み書き・検証・破損データの退避・エクスポート／インポート
  speech/speech.ts   Web Speech API
  hooks/             useTextSelection / useSpeech / useHashRoute
  screens/           教材一覧 / 教材編集 / 学習 / 復習
  components/        SelectionBar / Toast / ReviewCard
```

分け方の決まりは2つです。

- **`logic/` と `storage/` は、Reactを知らない**。状態の更新は「旧データ → 新データ」を返す関数で行い、元のデータを書き換えません。
- **画面の部品は、`localStorage` に直接触れない**。保存は `App` が1か所で行います。

時刻とIDは、関数の引数として外から渡します（`{ now, newId }`）。これで、純粋関数のままテストできます。

画面は4つで、`#/`（教材一覧）、`#/edit/:id`（編集）、`#/read/:id`（学習）、`#/review`（復習）のように、URLの `#` 以下で切り替えます。ルーターのライブラリは使わず、`hashchange` を読むだけです。サーバー側の設定が要らないので、静的に置くのに向いています。

## データの持ち方

持つものは、教材と復習項目の2つです。

```ts
type Material   = { id; title; english; japanese; createdAt; updatedAt };
type Occurrence = {            // 語句が登録された「1回の出会い」
  materialId: string | null;   // 教材が消えたら null
  start: number | null;        // 英文全体での位置。特定できなくなったら null
  end: number | null;
  sentenceSnapshot: string;    // 登録時の1文
  matchStart: number; matchEnd: number;   // その文の中での位置（強調用）
  createdAt: string;
};
type ReviewItem = {
  expression: string;          // 最初に登録された表記
  expressionKey: string;       // 重複判定用（小文字）
  meaning: string;             // 利用者が自分で入力する意味メモ
  occurrences: Occurrence[];
  hitCount: number;            // ★登録された回数
  status: "learning" | "ok";   // まだ怪しい / わかった
  reviewCount: number; lastReviewedAt: string | null;
  // …
};
```

**語句は教材に従属させず、教材とは別に持ちます。** 同じ表現が複数の教材から登録されたときは、1つの復習項目に、出現箇所（`Occurrence`）が増えていきます。教材を編集・削除しても、復習項目は消えません。これが、「登録データが失われないこと」を最優先にした設計の中心です。

文脈の `sentenceSnapshot` は、登録した時点の1文をコピーして持ちます。あとで教材の英文が書き換えられたり、教材ごと削除されたりしても、復習画面には文脈を出せます。

同じ表現かどうかは、`expressionKey` で決めます。空白をそろえて小文字にしただけの文字列です。`Due to` と `due to` は同じ、`delay` と `delayed` は別の表現として扱います。

## 選んだ範囲を、英文の位置で持つ

このアプリの技術的な芯は、**選択の位置を、DOMではなく文字列の位置で持つ**ことです。

### なぜDOMの位置ではだめか

英文は、読み取り専用の `div` に表示します。ただし、登録済みの語句には下線を付けるので、英文は**複数の `<span>` に分かれて**描画されます。ブラウザが返す選択（`window.getSelection()`）は、「どのノードの何文字目」という形です。これを保存すると、下線が増えて `span` の分け方が変わった途端に、意味を失います。

そこで、選択が変わった時点で、**英文全体の先頭からの文字数**に変換して持ちます。

```ts
function getTextOffset(container: HTMLElement, node: Node, offset: number): number {
  const range = document.createRange();
  range.selectNodeContents(container);
  range.setEnd(node, offset);
  return range.toString().length;
}
```

この変換が成り立つように、**表示される文字は、元の英文と1文字単位で一致させます**。表示用の文字や空白を足しません。`span` の間に余計な空白が入らないように書き、改行は `white-space: pre-wrap` で保ちます。

選択の開始と終了の**両方が英文の領域の中**にあるときだけ有効にします。はみ出した選択は無視します。

### ボタンを押すと、選択が消える

[聞き比べアプリ](eng-sound.md)と同じ問題が、ここにもあります。ボタンを押すと、ブラウザの選択が外れることがあります。そのため、ボタンを押した時点で選択を読み直すのではなく、**選択が変わった時点で持っておいた値**（`{ start, end, text }`）を使います。

さらに、ボタンを押した瞬間に選択が外れて、その通知が先に届く環境（主にスマートフォン）に備えて、次の2つを入れています。

- 操作バーの上で押下が始まったら、**その後の1秒間は、選択の変化を無視する**
- PCでは、操作バーのボタンの `mousedown` の既定動作を止めて、選択が外れないようにする

選択の通知は、`selectionchange` を基本に、`mouseup`・`touchend`・`keyup` も併用します。ブラウザごとに届き方が違うためです。独自の長押しの処理は書きません。スマートフォンの標準の選択ハンドルと選択メニューを、そのまま使えるようにするためです。

### 操作バーは、画面の下に固定する

選択の近くに浮かぶポップアップにすると、スマートフォンの標準の選択メニューと重なります。そのため、操作バーは**PCもスマートフォンも、画面の下部に固定**しました。セーフエリア（`env(safe-area-inset-bottom)`）を考え、英文の最後の行が隠れないよう、下に余白を取っています。

## 範囲の調整と、文脈の切り出し

登録の前に、選んだ範囲を次のように整えます。

1. 前後の空白・改行を、範囲から外す（`start` と `end` も直す）
2. 前後の句読点（`. , ; : ! ?` と引用符・括弧）を、範囲から外す
3. 内側の連続した空白・改行は、登録する文字列の上では、1つの半角スペースにする
4. 調整の結果が空になるなら、登録しない（操作バーで、ボタンを無効にする）

**単語の途中で切れた選択（`elayed` など）は、補正しません。** 利用者が選んだ範囲を尊重するためです。

文脈は、選んだ範囲を含む1文を、簡単なルールで切り出します。選択の位置から前へ、`.` `!` `?` か改行の直後まで戻り、後ろへ、同じ記号まで進みます。`Mr.` や `U.S.` のような略語では、文が途中で切れることがあります。実用上は、学習の文脈として足りると判断しました。

## ★登録

`★ 復習に追加`（または `S` キー）を押したときの動きは、次のとおりです。

| 状況 | 動作 | 通知 |
|---|---|---|
| 新しい表現 | 復習項目を作る（`hitCount = 1`、まだ怪しい） | 「…を復習に追加しました」 |
| 登録済みの表現 | `hitCount` を +1 し、まだ怪しいに戻す。同じ教材・同じ位置でなければ、出現箇所も足す | 「登録済みです。つまずき回数を +1 しました（★3）」 |

確認ダイアログは出しません。**読む流れを止めない**ことを優先し、代わりに、通知の `取り消す` で直前の1操作を戻せるようにしました。

取り消しは、専用の処理を持ちません。更新はすべて「旧データを書き換えず、新しいデータを返す」ので、**操作の前の `AppData` 全体を1つだけ持っておき、それに戻す**だけです。★登録と、復習項目の削除（これも確認なしで消す）の両方が、この仕組みを共有しています。通知は約3秒で消え、`aria-live="polite"` で読み上げられます。

## 下線の表示

学習画面では、登録した語句の位置に下線を引きます。**まだ怪しいは実線、わかったは点線**にして、色だけで区別しません。

語句どうしが重なることがあります（`delayed` と `has been delayed`）。そのため、すべての出現箇所の**開始位置と終了位置**で英文を区切り、区間ごとに下線の有無と種類を決めます。重なった区間は、まだ怪しいを優先します。

```ts
buildSegments(english, ranges)  // 区間の配列。つなぐと元の英文と1文字単位で一致する
```

位置が `null` の出現箇所や、他の教材の出現箇所は無視します。この関数は、表示の都合を知らない純粋関数なので、「重なる範囲」「範囲外」を単体でテストできます。

## 英文を編集・教材を削除したとき

教材の英文を書き換えると、すでに登録した語句の位置がずれます。そこで、その教材に紐づく出現箇所の位置を、次の順で再設定します。

1. 新しい英文の同じ位置の文字列が、同じ表現なら、そのまま
2. そうでなければ、新しい英文の中から、**大文字小文字を区別せず**表現を探し、元の位置にいちばん近いものへ移す（語の間の空白・改行の揺れは吸収する）
3. 見つからなければ、位置を `null` にする

どの場合も、**復習項目と文脈のスナップショットは消しません**。位置が `null` になった出現箇所は、下線が出なくなるだけで、復習では文脈として使えます。

教材を削除したときも同じです。出現箇所の `materialId` と位置を `null` にして、復習項目は残します。復習画面では、教材が削除された文脈には「元の教材は削除されています」と出し、和訳は出しません。

## 復習

出題の順番は、決まった規則で並べます。ランダムにはしません。

1. まだ怪しいを先に
2. `hitCount`（つまずいた回数）の多い順
3. 最後に復習した日時が古い順（一度も復習していないものを最優先）

復習の流れは、次のとおりです。

- 開始時の項目の ID の並びを、**その場で固定**します。途中で状態が変わっても、**同じ周回の中で再出題しません**（1周で終わる）。
- カードには、最初は「表現」と「元の英文」だけを出します。`意味を見る` で、利用者が自分で書いた意味メモを出します。意味メモが空なら、その場で書き込めます（フォーカスが外れたら保存）。
- 元の英文の中では、該当する語句を**太字と背景色**で強調します。
- 同じ表現が複数の教材から登録されているときは、いちばん新しい文脈を先に出し、`他の文脈を見る（n件）` で切り替えます。
- `わかった` / `まだ怪しい` の判定は、**押した時点で保存**します。途中で終了しても失われません。

### 元の英文へ戻る

復習が終わると、今回出てきた語句の**元の教材**が一覧に出て、`読む` で学習画面へ戻れます。

> 復習する → 元の英文へ戻って読み直す

この導線は、アプリの中心の輪を閉じる部分なので、省略しませんでした。

## 保存

データは、`localStorage` の1つのキー（`english-reading-review:v1`）に、まとめて保存します。変更のたびに保存します。

### 壊れたデータを、上書きしない

起動時に、読み込んだデータの形を検証します。形が正しくなければ、**そのデータを別のキー（`…:corrupted-<日時>`）にそのまま退避してから**、空の状態で始めます。画面の上部には「データを読み込めませんでした」と出ます。

退避そのものに失敗した場合は、元のデータを守るため、**保存とインポートを止めます**。空のデータで、壊れたデータを上書きしてしまわないためです。保存に失敗したとき（容量超過など）は、「保存に失敗しました。エクスポートでデータを退避してください。」と出します。

検証は、形だけでなく、たとえば出現箇所の `start` と `end` が「両方 `null`」か「両方整数」かまで見ます。

### エクスポートとインポート

データはブラウザの中にしかないので、**書き出しと取り込みが、データを失わないための唯一の手段**です。JSONファイルとして書き出し、別の端末で取り込めます。取り込みは、内容を検証してから**置き換え**ます（混ぜません）。

- 検証に失敗したときは、確認も出さず、既存のデータを一切変えない
- 検証に成功したときだけ、「現在のデータは置き換えられます」と確認する
- 保存に失敗したときも、既存のデータは変えない

端末の間でデータは自動では同期されません。クラウド同期は、このアプリには入れていません。必要になったら、[英文学習アプリ](eng-sentence.md)の暗号化同期の作りを参考にして、別の段階で考える予定です。

## 読み上げ

読み上げは、全文・選んだ語句・復習カードの表現の3か所にあります。[聞き比べアプリ](eng-sound.md)ほど複雑にせず、必要な部分だけを使っています。

- 英語の音声を、`en-US` → `en` で始まるもの → ブラウザの既定、の順で選ぶ（`en_US` のような形も同じ扱い）
- 音声の一覧は後から読み込まれることがあるので、最初の取得と `voiceschanged` の両方を受ける
- 新しい読み上げの前には、必ず `cancel()` する
- 速度は `1.0x` と `0.75x` の2択。設定は別のキーに保存する
- どのボタンが読み上げ中かは、番号（トークン）で照合する。古い発話の終了通知が遅れて届いても、新しい読み上げの表示を消さない
- 画面を離れるときと、部品が破棄されるときは、読み上げを止める
- ブラウザが対応していなければ、ボタンごと出さない。ほかの機能は、そのまま使える

## テスト

Vitest で、**`logic/` と `storage/` の純粋関数を、ブラウザなしで**テストしています。

- 範囲の調整（空白・改行・句読点、内側の空白、空の選択の拒否）、キーの生成
- 文の切り出し（先頭・末尾・改行で区切られた文、強調位置）
- ★登録（新規、再登録で増える、同位置で出現箇所が重複しない、別教材で出現箇所が増える、元に戻る）
- 英文の編集での位置の再設定（そのまま、前に挿入、複数のうち近いもの、消えた）、教材の削除
- 出題の順番、下線の区間分割（重なり、範囲外）
- 保存と読み込み、壊れたデータの退避、不正な取り込みで既存データが変わらないこと
- 音声の選び方

DOMの選択の実際の挙動と、読み上げの音質は、自動テストの対象外です。実機で確かめる項目を、READMEのチェックリストにまとめています（PCの Chrome / Edge、スマートフォンの iOS Safari / Android Chrome）。

## 公開

Vite の `base` を `./` にして、ビルド結果の `dist/` を、そのまま静的に置けるようにしています。配信は、Cloudflare Workers の静的アセット配信で行う構成です。Worker・D1・認証は使いません。`npm run deploy:dry` で設定を確かめてから、`npm run deploy` で配備します。

データは、**配信先のURLごと、ブラウザごと**の `localStorage` に入ります。開発用の `localhost` と、公開したURLでは、データは別です。

## 限界と使うときの注意

- データはブラウザの中にだけ保存されます。ブラウザのデータを消したり、端末を変えたりすると失われます。定期的なエクスポートをおすすめします。
- PCとスマートフォンの間では、自動では同期されません。エクスポートとインポートで移します。
- 読み上げの声質と発音は、OSとブラウザで変わります。長い英文は、途中で止まることがあります。
- 文の切り出しは簡単なルールなので、`Mr.` や `U.S.` などで、文が途中で切れることがあります。
- 英文を編集して語句が見つからなくなると、その出現箇所の下線は消えます（復習項目と文脈は残ります）。
- 自動翻訳・辞書・文法の解説・間隔反復（忘却曲線）・学習統計は、このアプリには入れていません。意味は、利用者が自分で書きます。
