# 連続2ページPDFリーダー

<p class="about-work-links">
<a class="arrow-link" href="https://github.com/minnanosaiban/pdf-reader" target="_blank" rel="noopener"><i class="bi bi-github"></i> GitHub</a>
</p>

**開発中です。** 公開サイトはまだありません（ソースコードは GitHub にあります）。このページは、設計と、作るうえで判断したことの解説です。

紙の資料を2ページ並べて読むように、**連続する任意の2ページ**（Page 3 \| Page 4 → Page 4 \| Page 5 → …）を同時に大きく表示するPDFリーダーです。蛍光マーカー、ライン、手書き風の文字を書き込めます。サーバーはなく、処理はすべてブラウザの中で行います。**開いたPDFも、書き込みも、自分のパソコンの外に出ません。**

見開きの本をめくる「フリップブック」や、Acrobat の簡易版は目指していません。優先する順に、次の5つを決めて作っています。

1. PDF2ページを、可能な限り大きく表示する
2. ホイールと左右キーで、1ページずつ確実に移動する
3. 書き込みが、正しいページ位置に残る
4. PDF本文をUIで遮らない
5. 不要な機能を増やさない

## 全体の構成

React + TypeScript + Vite で、PDFの描画に PDF.js を使っています。

```
src/
  lib/          判断ロジック（純粋関数）と、描画・保存
  hooks/        useSpreadLayout / useWheelNavigation / usePageRatios
  components/   ツールバー・2ページ表示・ページ・ポップオーバー・設定
  App.tsx       状態管理と、キーボード・保存の接続
```

方針は、**判断ロジックを画面から切り離す**ことです。レイアウトの計算、ホイールの状態遷移、クリックの当たり判定、ストロークのページ境界処理、取り消し履歴、文書の識別。これらは、DOM もタイマーも知らない関数として書き、単体テストで確かめています。画面（React）は、その結果を表示してイベントを渡すだけにしています。

## 2ページを「大きく」表示する

### 縦幅を基準にし、足りないときだけ縮める

2ページの表示サイズは、次の順で決めます。

1. 作業領域（ツールバーを除いた部分）から、上下左右の最小余白を引く
2. ページ高さを、利用できる高さいっぱいにする
3. 2ページ分の幅（比率の合計 × 高さ ＋ ページ間隔）が横幅を超えるときだけ、高さを縮める

これを「フィットサイズ」と呼び、倍率100％の基準にします。A4 固定にはせず、PDF.js から各ページの実際の縦横比を取得するので、縦向きと横向きが並んでも、**2ページの表示高さはそろい**、幅だけが比率で決まります。最後のページで右側が空くときは、左と同じ大きさの空白を確保し、左ページの位置が動かないようにしています。

余白は、CSS の `clamp()` で書いた値を CSS と JavaScript の両方で使うため、計算元は JavaScript 側の1か所にして、CSS 変数はその値から設定しています。値が二重になって、ずれることを防ぐためです。

### 倍率は「描画サイズそのもの」を変える

書き込みやすいように、表示ボタンから90％・80％に縮小して、周りに余裕を持たせられます。ここで、**CSS の `transform: scale()` は使いません。** 縮小したとき、ポインターの座標とAnnotationの座標の変換が複雑になり、当たり判定や入力位置がずれやすく、縮小後の文字がぼやけることもあるからです。代わりに、PDF.js の描画サイズ自体を倍率に合わせて計算し直します。

- 倍率の基準は、PDFの実寸ではなく常にフィットサイズ。ウィンドウの大きさが変われば、フィットサイズを計算し直してから倍率を掛ける
- 100％を超える拡大は作らない。初期状態を「可能な限り大きく」にしているため、縮小は利用者が選んだときだけ
- Canvas の内部解像度は「表示サイズ × devicePixelRatio」。1ページあたりの上限（約1,677万ピクセル）を超えるときは、devicePixelRatio を下げる
- 連続した倍率変更やリサイズは、最後の1回だけ描画する。古い描画タスクは、新しい描画を始める前にキャンセルする
- 描画したページは「ページ番号 ＋ 表示サイズ ＋ devicePixelRatio」をキーにして覚えておき、`Page 3 | 4` から `Page 4 | 5` へ移るときに、Page 4 を描き直さない

1ページは、3つのレイヤーを重ねて作っています。

```
PDFPage
├─ PDFCanvas            PDF.js によるページ描画だけ
├─ PageAnnotationLayer  保存済みの書き込みの表示（クリックを受け付けない）
└─ InteractionLayer     筆記具の入力と、描いている最中の線の表示
```

PDF.js のテキストレイヤー（本文の文字選択）は使っていません。文字選択はこのアプリの目的ではなく、レイヤーが増えて入力の取り合いが起きるためです。

## ホイールで「1ページずつ」進める

ホイールは、トラックパッドの慣性スクロールが厄介です。指を離したあとも入力が数百ミリ秒続くので、素朴に作ると、1回の操作で2ページ、3ページと進んでしまいます。そこで、**1回の連続したホイール操作（ジェスチャー）につき、最大1ページ**にしています。

状態は3つです。

| 状態 | 意味 |
|---|---|
| `idle` | 入力を待っている |
| `collecting` | 移動量をためている（100px で1ページ移動） |
| `latched` | 移動した。ジェスチャーが終わるまで、次の移動をしない |

入力が180ms途切れたら、`idle` に戻ります。判断のポイントは2つあります。

- **`latched` 中は、方向が反転しても無視する。** 慣性スクロールの揺り戻しで、直前の移動と逆向きにもう1ページ動くのを防ぐため。`collecting` 中の反転は、ためた量をリセットして、新しい方向でためなおす
- **ページ遷移アニメーション中の入力は、移動には使わないが、終了タイマーは延長する。** アニメーション（約200ms）が、終了判定の時間（180ms）より長いので、延長しないと、慣性スクロールが続く途中で `idle` に戻り、アニメーション終了後の入力で2ページ目へ進んでしまう

この判断を、時間も画面も持たない関数（累積と閾値判定）と、タイマーを持つ薄いコントローラーに分けて、タイマーは単体テストで動かして確かめています（慣性入力が続く間は1ページだけ、アニメーション中の入力でタイマーが延びる、など）。Ctrl / Cmd を押しているホイール（ブラウザのズームやピンチ）、入力欄の上、書き込み中は、ページ送りに使いません。

ホイールを受け付ける範囲は、PDFの外の余白を含む作業領域全体です。縮小して余白ができても、余白でホイールが効きます。

## 書き込みを「ページ内の位置」で持つ

書き込みは、**ページの中の正規化座標（0〜1）** で保存します。ページの左上を (0, 0)、右下を (1, 1) とした割合です。線の太さや文字の大きさも、ページの高さに対する割合にします。こうすると、100％で書いたものが80％でも同じ位置・同じ比率で表示され、ウィンドウの大きさにも左右されません。ページが左から右、右から左へ移っても、書き込みは「そのページ」に付いたままです。

### ページの外へはみ出した線

縮小するとPDFの周りに余白ができて、ペンがページの外へ出やすくなります。このとき、**ページの外の点を、ページの端へ押し込んで（clamp して）保存すると、ページの縁に沿った線が残ってしまいます。** そこで、次のように決めています。

- PDFの外の余白からは、描き始めない
- 描き始めたら、ポインターをキャプチャして、ページの外へ出ても入力を受け取り続ける
- ページの外へ出たら、直前の点と外の点を結ぶ線分と、ページ境界との**交点**を最後の点にして、その時点で線を終える
- 一度終えた線は、ページ内へ戻っても再開しない。左ページから右ページへまたがる線も作らない

交点の計算は純粋関数にして、右・上へ出る場合や角から出る場合をテストしています。

### 蛍光マーカーと線

マーカーは半透明で、幅と濃さにわずかな揺れを持たせ、完全な長方形にならないようにしています。線は細く、ほぼ不透明で、微小な手描き感を付けています。揺れは、書き込みの ID から決まる擬似乱数なので、再描画しても形が変わりません。手書き風の文字は、キーボード入力と手書き風フォントの組み合わせです（フォントは同梱し、外部の配信サービスは使いません）。

### 選択は「座標で当たり判定」する

閲覧ツールのときに書き込みをクリックして選び、削除や再編集ができます。クリックの受け取りは、書き込みの DOM 要素ごとではなく、**ページ要素でクリックを受けて、座標で判定**します。表示専用のレイヤーが、SVG でも Canvas でも、選択の動作が変わらないようにするためです。

当たり判定は、次のとおりです。

- 線は、クリック位置から各線分までの最短距離で判定する（許容幅は、表示上の線幅の半分 ＋ 4px）。線を囲む矩形全体は当たりにしないので、大きな丸で囲んだ線の内側をクリックしても選択されない
- 距離は、正規化座標を表示サイズのpxに戻してから比べる。許容幅が、倍率にかかわらず画面上のpxで一定になる
- 重なっているときは、後から作ったものを優先する

## 取り消し・やり直しと保存

取り消し・やり直しの対象は、書き込みの追加・削除・テキストの変更です。テキストの再編集は、1回の操作として取り消せます。倍率と配置の変更は、取り消しの対象にしません。文字入力中の Ctrl / Cmd + Z は、入力欄の文字の取り消しとして扱います。

### 同じPDFだと、どう判断するか

書き込みや表示状態は、IndexedDB に自動保存します（変更の500ms後）。保存の鍵になる「文書の識別」は、ファイル名ではなく、**PDFの中身のハッシュ（SHA-256）** にしました。ファイル名を変えても、コピーしても、同じPDFなら同じ書き込みが戻り、1バイトでも違えば別の文書として扱います。

50MBを超える大きなファイルは、全体を読むと時間とメモリがかかるので、サイズ ＋ 先頭1MB ＋ 末尾1MBのハッシュにしています。この場合、先頭・末尾・サイズが一致する別のPDFを同じと誤認する可能性がありますが、実用上はまれと判断して許容しています。また、PDFを編集して保存し直すと中身が変わるので、以前の書き込みは復元されません。

倍率と配置は、全PDF共通ではなく、PDFごとに保存します。保存するのは割合と配置だけで、ピクセル寸法は保存しません。開くたびに、画面の大きさからフィットサイズを計算し直し、保存された倍率を掛けます。

## 作らなかったもの

仕様の段階で、次のものは作らないと決めています。AI・OCR・要約・翻訳、クラウド同期、PDF全文検索、本文の文字選択、常設のサムネイルやサイドバー、100％を超える拡大、PDFの外の余白への書き込み、PDFファイルへの書き込みの焼き込み。「PDFを大きく読み、正しい位置に書き込む」ことを最優先にして、画面を遮るものと、機能の数を増やさないためです。
