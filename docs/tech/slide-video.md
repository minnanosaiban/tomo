# スライド動画メーカー

<p class="about-work-links">
<a class="arrow-link" href="https://slide-video-c0s.pages.dev/" target="_blank" rel="noopener"><i class="bi bi-box-arrow-up-right"></i> 公開サイト</a>
<a class="arrow-link" href="https://github.com/minnanosaiban/slide-video" target="_blank" rel="noopener"><i class="bi bi-github"></i> GitHub</a>
</p>

画像やPDFから、X（旧Twitter）に投稿できるスライド動画（MP4）を作る、ブラウザだけで動くツールです。サーバーはなく、静的ファイルを Cloudflare Pages に置いているだけです。**画像もPDFも自分のパソコンの外に出ません。** 読み込みも、描画も、動画への変換も、すべてブラウザの中で行います。

このページは、その仕組みと、作るうえで判断したことの解説です。

## 作った経緯

[応援傍聴ナビ](court-calendar.md)の事件ページには、複数の画像が流れるカルーセルがあります。ここにPDFも登録できるようにしたところ（1ページを1枚の画像にして登録）、「この見せ方を動画にして、Xに投稿したい」という要望が出てきました。それが、このツールの出発点です。

ただし、事件ページのカルーセルをそのまま録画しても、Xには向きません。Xのタイムラインでは動画が小さく、音なしで自動再生されます。中央の1枚が大きく、左右の隣が切れて見えるカルーセルでは、**文字が小さくて読めません**。そこで、Webページ風の見せ方は残しつつ、Xで読みやすい**全画面系**の見せ方を加えました。

## 全体の構成

ビルド工程のない素のHTML / CSS / JavaScript です。バンドラーもフレームワークも使っていません。

```
public/
  index.html      画面（スタイル選択・設定・プレビュー）
  app.js          読み込み・描画・書き出しのすべて
  style.css       見た目（sidenote・pdf-tools と共通のデザイン）
  vendor/
    pdfjs/        PDFを画像にする（pdf.js）
    mp4-muxer/    動画データをMP4ファイルにまとめる
```

処理は、次の3段に分かれています。

| 段 | やること | 使うもの |
|---|---|---|
| 読み込み | 画像・PDFを、1枚ずつの画像（`ImageBitmap`）にする | pdf.js、`createImageBitmap` |
| 描画 | ある時刻の1コマを、canvasに描く | Canvas 2D |
| 書き出し | 1コマずつ動画に変換し、MP4にまとめる | WebCodecs、mp4-muxer |

### 外部通信をなくす

pdf.js と mp4-muxer は、CDN から読み込まず、リポジトリへ同梱しています。「画像は送信されない」と謳うツールが、ページを開くたびに外部サーバーへアクセスしているのは筋が悪いためです（[PDFツール](pdf-tools.md)と同じ判断です）。

## PDFを画像にする

PDFは、pdf.js で**1ページずつ canvas に描き**、それを画像として保持します。幅1920pxで描くので、全画面でも文字がにじみにくくなります。背景は白で塗ってから描きます。PDFの透明部分が、動画の中で黒く抜けないようにするためです。

画像は `ImageBitmap` にして持ちます。描画のたびに画像をデコードし直さずに済むので、動画の書き出し中に、同じ画像を何百回も描いても重くなりません。1ファイルのページ数は200ページまでにしています。

## 描画は「時刻だけで決まる関数」

このツールの中心は、`drawFrame(t, 設定)` という1つの関数です。**時刻 `t`（秒）と設定を渡すと、その瞬間の1コマが描かれます。** 前のコマの状態に依存しません。

同じ関数を、3か所で使い回しています。

| 使う場面 | `t` の与え方 |
|---|---|
| プレビュー | 再生開始からの経過時間（`requestAnimationFrame`） |
| 書き出し | `コマ番号 ÷ 30`（1コマずつ決まった値） |
| トップの見本 | 見本スライド3枚を、小さいcanvasへ（スタイルを選ぶと切り替わる） |

プレビューで見た動きと、書き出された動画の動きが**一致する**のは、この作りのおかげです。書き出しは実時間で録画するのではなく、「0秒の絵、1/30秒の絵、…」と決まった時刻の絵を順に作ります。パソコンが重くても、コマ落ちしません。

### 時間の流れ

1枚ずつ「見せる時間（保持）」と「切り替える時間（移動）」を交互に並べます。時刻から「いま何枚目か」を小数で返す関数があり、保持中は整数（3.0 なら3枚目）、切り替え中は小数（3.4 なら3枚目から4枚目へ4割進んだ）になります。この小数が、すべてのスタイルの動きの元です。

動きは、一定の速さではなく、始まりと終わりがゆっくりな**イーズイン・アウト**（3次式）にしています。一定の速さだと、機械的に見えるためです。

## 8つの見せ方

どのスタイルも、上の小数の位置から絵を作ります。

| スタイル | 作り方 |
|---|---|
| カルーセル | 中央の1枚を1.15倍、左右を0.92倍・半透明に。位置に応じて連続的に補間 |
| ページめくり | 右端から折り目が左へ進む。折り目の左に、めくれた紙の裏側を反転して描き、陰影をつける |
| カード飛ばし | 手前の1枚が傾きながら左へ飛び、下から次の1枚が大きくなって現れる |
| キューブ回転 | 現在と次の2枚を、幅を縮めながら横に並べる（疑似3D） |
| 横スライド | 全画面で右から左へ押し出す |
| 枠付き1枚 | 余白と影のある1枚が、横へ流れる |
| フェード | 全画面で重ねて切り替える |
| ゆっくりズーム | フェードに加えて、各スライドを時間とともに少し拡大する |

カルーセルは、事件ページで使っているカルーセル（Swiper）の設定値（中央を大きく・左右を薄く・広い画面で2.2枚）に合わせました。Webページでの見え方と同じ雰囲気の動画になります。

### 3Dは使っていない

キューブ回転は3Dに見えますが、実際は**幅を変えた2枚の絵を並べているだけ**です。回転角から2枚の幅（角度の余弦・正弦）を決め、立体に見える分だけ高さを少し縮め、奥に回る面を暗くします。3Dライブラリを使わずに済み、プレビューも書き出しも、他のスタイルと同じ仕組みで動きます。

ページめくりも同じです。折り目の左側に、同じ絵を左右反転して描き、紙の裏側のように白っぽく陰影をつけるだけです。

### 進捗バーとページ番号

全画面系は、画面下に進捗バー、右上に「3 / 23」のページ番号を重ねられます。動画を途中から見た人にも、いま全体のどこかが分かります。カルーセルは、事件ページと同じ見た目のため付けません。

## 動画にする：WebCodecs

書き出しには、ブラウザ標準の **WebCodecs**（`VideoEncoder`）を使っています。canvas の絵を1コマずつ `VideoFrame` にして渡すと、H.264 の圧縮データが返ってきます。

```js
const vf = new VideoFrame(cv, { timestamp: Math.round(f * 1e6 / fps), duration: Math.round(1e6 / fps) });
enc.encode(vf, { keyFrame: f % (fps * 2) === 0 });
vf.close();
```

圧縮データは、そのままでは動画ファイルになりません。**mp4-muxer** が、時刻情報つきで MP4 の形にまとめます。書き出し後にファイルの先頭へ再生に必要な情報を置く設定（`fastStart`）にして、ブラウザやXで再生が始まりやすくしています。

### Xの条件に合わせる

| 項目 | 設定 | 理由 |
|---|---|---|
| 形式 | MP4（H.264） | Xが確実に受け付ける形式 |
| コマ数 | 30fps | 資料の動画では十分で、ファイルも小さい |
| 音声 | なし | スライドのみ。Xは音なしの動画も再生できる |
| ビットレート | 画素数 × 4 | 文字が多い画面でも崩れにくい（1080pで約8Mbps） |
| キーフレーム | 2秒ごと | 途中からの再生・シークを軽くする |

H.264 のプロファイルは、高いものから順に、このパソコンで使えるかを調べて選びます。使えない場合は VP9 に切り替え、「XはH.264が確実なので、別のパソコンで作り直してください」と画面に出します。**黙って別形式にせず、投稿できない可能性を知らせる**ためです。

Xの上限（通常のアカウントは2分20秒・512MB）は、画面に常に表示します。超えると、長さの表示が警告色になり、「140秒以内に収める」ボタンで、1枚を見せる秒数が自動で縮まります。書き出し後にも、超えていれば警告を出します。

### 書き出し中に固まらせない

1コマずつ処理する間、ブラウザが固まらないよう、エンコーダーの待ち行列が溜まったら、いったん処理を譲って待ちます。進捗バーも一定コマごとに更新します。長い動画（1000コマ以上）でも、画面が止まりません。

## デザインはほかのツールと共通

画面の作りは、[サイドノート作成](sidenote.md)・[PDFツール](pdf-tools.md)と同じです。上にヒーロー（タイトル・説明・切り替えボタン・イメージ図）、下にカード、最後に免責事項を置いています。スタイルのボタンは、PDFツールの「機能」ボタンと同じ位置です。

トップ右のイメージ図は、選んだスタイルで**実際に動く**小さなプレビューです。スタイルを切り替えると、すぐ別の動きになります。同じ `drawFrame` を使うので、図と動画の動きが食い違うことはありません。

## 限界と使うときの注意

- **ChromeかEdgeの新しい版**が必要です（WebCodecs が使えるブラウザ）
- **音声は付けられません**
- 書き出し中は、そのタブを前面に出しておいてください（裏に回ると、ブラウザが処理を遅くします）
- 書き出した動画は、いったんメモリに溜めてから保存します。枚数が多く、サイズも大きい動画では、メモリを多く使います
- キューブ回転・ページめくりは疑似的な表現です。本物の3D・紙の物理とは違います
- 投稿前に、動画の中身（個人情報・著作権）を、必ず自分の目で確認してください
